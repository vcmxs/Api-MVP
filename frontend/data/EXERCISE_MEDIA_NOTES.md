# Exercise media reference

- `exercise-video-map.json` contains the mobile app's current YouTube links, matched to 155 names in the public Railway exercise catalog during implementation (2026-11-05). These videos are placeholders belonging to a friend, not final exercise media. Keep that limitation in mind when reviewing or expanding this map; do not treat the links as permanent, verified coaching content.
- The long-term goal is to use exercise GIFs. `exercise-gif-map.json` is intentionally empty until approved GIF assets and name mappings are available.
- The mobile static descriptions are also retained for the About/Instructions section because the live Railway catalog did not expose a description field in the read-only response. One empty generic description is intentionally omitted.
- The Railway catalog remains the source of the current exercise list. The web detail fetches that catalog and only uses mapped media for a uniquely matched exercise name; do not copy this media map into Railway. At the time of the read-only check, its `video_url` field was populated with non-URL placeholder text (for example, `EJEMPLO`); the web validates any catalog URL and prefers the mobile static URL rather than attempting to embed that text.
- If the Railway catalog changes, reconcile names against the mobile static map before adding or remapping URLs. Normalize accents/case/punctuation only for matching; manually review any ambiguous names.
- **Name-based YouTube fallback (2026-11-06):** when an exercise has no static map entry and no valid catalog `video_url`, the web asks the API (`GET /api/v1/exercises/video?name=<exercise name>`) for a reference video. `services/youtubeSearchService.js` searches YouTube (technique-biased query), ranks the results so a title that actually names the exercise and mentions technique wins, and returns `{ videoId, title, thumbnailUrl, embedUrl, searchUrl }`. The backend caches hits for 7 days and misses for 6 hours in memory; the frontend also de-duplicates lookups per exercise name for the page session.
- Those fallback videos are heuristic search picks, not curated or verified coaching content. Treat them like the static map: provisional. If a wrong video is cached, restart the API (clears the in-memory cache) or map the exercise explicitly in `exercise-video-map.json`, which always takes precedence over the fallback.
- If the lookup finds nothing, the About tab shows the "no reference video" message plus a "Search on YouTube" link instead of embedding an unrelated video. Workout exercises can have names that are not in the catalog at all (for example `Bicep Curls`), and the fallback still resolves them because it works from the name.
