# Web-to-Mobile Feature Ledger

Use this ledger to record each **new web feature or meaningful user-facing addition** so we can review its mobile implications later. This is a forward-looking record; it is not an audit or comparison of existing web and mobile features.

## Workflow

1. When implementing a web addition, add a row here in the same change/task.
2. Start its mobile status as **Review needed**. Do not assume it must be identical or immediately ported.
3. Decide with the owner whether it applies to mobile, and record scope/notes.
4. Update the status as mobile work is planned, underway, completed, or intentionally not needed. Link the relevant web/mobile files or work item when useful.

## Status meanings

- **Review needed** — web addition is recorded; mobile applicability has not been decided.
- **Planned** — mobile port is wanted but not started.
- **In progress** — mobile implementation is underway.
- **Ported** — mobile implementation is complete; validate behavior before release.
- **Not needed** — intentionally web-only or otherwise out of mobile scope; include a short reason.
